# Dumpsta-Engine 1.0.0

The first release with a compatibility promise. From here the public surface in
`engine/tests/public_surface.txt` follows SemVer per ADR-0011: removing or changing a line is a
major release, adding one is a minor release, and everything under `_core` and `_private`,
including every repair of an upstream endpoint, is a patch.

This release is prepared and not published. There is no configured destination.

## What it does

Every capability is on both `SyncClient` and `AsyncClient`, with the same parameters and the same
return type, and each one is a `dumpsta` subcommand.

Reads:

- `thread_messages(thread_fbid, *, after=None, newer_than_message_id=None) -> Page[Message]`,
  one page of a direct thread
- `profile(username) -> Profile` and `profile_by_id(user_id) -> Profile`, the second carrying
  `friendship_status` for another account
- `feed(*, after=None) -> Page[FeedItem]`, the home timeline, whose items are posts,
  advertisements and suggestions
- `notes() -> tuple[Note, ...]`, the notes tray
- `post(code) -> PostDetail`, one post by its shortcode
- `comments(post_pk, *, after=None) -> Page[Comment]`, one page of a post's comments

Writes, each sent once and never retried by the engine:

- `like(post_pk)` and `unlike(post_pk)`
- `comment(post_pk, text) -> Comment` and `delete_comment(post_pk, comment_id)`
- `set_note(text, *, audience=NoteAudience.CLOSE_FRIENDS) -> Note` and `delete_note(note_id)`
- `follow(user_id)` and `unfollow(user_id)`, keyed on the numeric account id
- `send_message(thread_fbid, text) -> SentMessage` and `unsend_message(thread_fbid, message_id)`

A write whose connection fails in flight raises `OutcomeUnknown`, and each write's documentation
names the read that settles what happened.

New messages:

- `AsyncClient.events(*, since=None)`, an async iterator of `Event`
- `SyncClient.events(*, since=None, on_event=None) -> EventListener`, with `start`, `stop`,
  `drain` and `wait_for_events`, the last two safe from any thread but the engine's own loop
  thread, which is how an embedding app calls them
- Events are `NewMessage`, `EventsDropped` for a gap, with `count` None when the gap's size is
  unknown, and `ListenerStopped`, which carries the exception that ended the listener

Around them:

- `Session`, adopted from cookies copied out of a browser, saved and loaded as JSON with
  `schema_version` 1 and owner-only permissions
- `Behavior`, with the presets `PARITY`, the default, `EXPORT` and `FAST`, and
  `with_behavior` on each client for a scoped client that shares the account's pacer
- One exception hierarchy, a checkpoint never retried, and every public error mapped to its own
  `dumpsta` exit code

## Known limitations

- Posting is not in this release. It is planned as `1.1.0`, an additive minor release.
- The engine adopts an existing browser session and cannot log in.
- The listener polls the inbox every 60 s by default. It does not yet use the
  `newer_than_message_id` filter the upstream honours, and it marks nothing seen.
- Every `dumpsta` invocation is a new process with a fresh pacer, so the write budget and the
  write stop do not carry from one command to the next. Closed after 1.0.0 by the pacing
  ledger, E1 item 8 of [../web-parity-plan.md](../web-parity-plan.md).
- Human timing rests on one measured sample, taken on one day.
- Token lifetime has a lower bound and no upper bound. Stored tokens 2 h 52 min old were accepted
  on 2026-09-23, which raises the earlier bound of 16 minutes. The engine re-reads its tokens
  when the upstream rejects them either way.
- Everything was measured on one account, from one residential IP, against the web surface.
  Group threads, the mobile API and any non-residential network are unmeasured.
- aarch64 macOS on CPython 3.12 is the only verified platform. Intel is unverified.
- The source distribution ships the gates and the scripts they load. Seven gates read git, the
  additive freeze through `git show` of the baseline commit and the sdist check through
  `git check-ignore`, so they fail outside a git checkout. The recorded oracle's fixtures stay
  local, so its gates skip outside the author's checkout.

## Departures from browser parity

The default behavior aims to send what a browser sends around each action. These are the places
it does not, each recorded in `docs/web-request-contract.md`:

- The notes tray read is sent alone. A browser sends it as one of ten queries in an inbox load,
  which is not modelled.
- A post read, a like and an unlike are each sent alone, without the post page's document and
  companions, and without the Relay layer's `actor_id` and the feed item's
  `organic_tracking_token`.
- A comment page read, a comment and a comment delete are each sent alone. The first comment page
  uses the pagination query rather than the page's own container query, and the page size of 10
  is an assumption.
- A follow and an unfollow are each sent alone, without the page the follow is made from.
- A direct text send and an unsend are each sent alone, with the thread page as the referer, and
  without the browser's performance logging fields.
- A note set and a note delete are each sent alone, without the inbox load and the composer's
  bootloader requests around them.
- The listener's polling is itself a departure, whatever the preset, because no browser was seen
  re-reading the inbox listing on a timer, and it leaves out the thread open and the mark-read
  mutation a browser sends around a thread it reads.

## Upstream repairs

None. This is the first release with a version promise, so there is no earlier release to repair.
