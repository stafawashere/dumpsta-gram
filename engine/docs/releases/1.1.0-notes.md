# Dumpsta-Engine 1.1.0

The first minor release under the compatibility promise of `1.0.0`, and the release of phase E1 of
[../web-parity-plan.md](../web-parity-plan.md). Every change to the public surface is an addition:
`tests/public_surface.txt` grew from 397 lines at `v1.0.0` to 536, 139 lines added and none
removed or changed. Code written against `1.0.0` runs unchanged.

This release is prepared and not published. There is no configured destination.

## What it adds

### Domain namespaces

Both clients gain five namespace properties, `direct`, `feeds`, `media`, `profiles` and `social`,
each returning a small object with an awaitable form on `AsyncClient` and a blocking form on
`SyncClient` (W1, W19). New capabilities live on a namespace and not on the client. Each of the
17 flat methods of `1.0.0` stays and gains one alias with the same parameters and return type
(W21):

| Flat method | Alias |
|---|---|
| `thread_messages` | `direct.messages` |
| `send_message`, `unsend_message` | `direct.send`, `direct.unsend` |
| `notes`, `set_note`, `delete_note` | `direct.notes`, `direct.set_note`, `direct.delete_note` |
| `feed` | `feeds.home` |
| `post` | `media.by_code` |
| `like`, `unlike` | `media.like`, `media.unlike` |
| `comments`, `comment`, `delete_comment` | `media.comments`, `media.comment`, `media.delete_comment` |
| `profile`, `profile_by_id` | `profiles.by_username`, `profiles.by_id` |
| `follow`, `unfollow` | `social.follow`, `social.unfollow` |

The timelines are `feeds` and the notes sit on `direct` because `feed` and `notes` were already
flat method names in the frozen baseline (W19). `stories`, `search` and `account` do not exist yet
and arrive with their first method (W20). `events` stays on the client and has no alias.

### Pagination iterators

On the namespaces only (W24):

- `direct.iter_messages(thread_fbid, *, limit, after=None, newer_than_message_id=None)`
- `feeds.iter_home(*, limit, after=None)`
- `media.iter_comments(post_pk, *, limit, after=None)`

`limit` is required, keyword only, counts items, and `None` reads to the end (W23). A walk ends
only on `has_next_page`, reads each page through the namespace's own paced page read, and reads
nothing ahead. The awaitable form returns an `AsyncIterator`, the blocking form is a generator.

### Media model and downloads

`Post` and `PostDetail` gain five fields with defaults: `videos` (`VideoRendition`),
`video_duration` in seconds, `has_audio`, `audio` (`MediaAudio`, with `AudioKind` `MUSIC` or
`ORIGINAL_SOUND`) and `carousel_children` (`CarouselChild`) (W28).
`media.download(rendition, path, *, overwrite=False) -> Path` fetches one image or video
rendition from the `cdninstagram.com` family over `https`, takes no pacer slot, writes
atomically, refuses an existing file unless told, and checks `content-length` where one is sent
(W26, W27, W29).

### Posting

On `client.media`, both clients, with no flat twin (W37):

- `publish_photo(image, *, caption="") -> PublishedPost`
- `publish_carousel(images, *, caption="") -> PublishedPost`, two images or more
- `delete_post(post_pk, code) -> None`, the viewer's own post only

`PublishedPost` carries `pk`, `id`, `code`, `taken_at`, `media_type` and `upload_ids`. An image
is a JPEG, as bytes or a path, and anything else is refused before a request. The read that
confirms a post is up is `media.by_code`. The command line gains `dumpsta publish-photo`,
`publish-carousel` and `delete-post`, each of which confirms itself with a read in the same
process.

### Pacing across processes

A client built with `from_session_file(path)` keeps the write budget and the write stop in
`<path>.ledger` under a `flock`, so every process on one account shares one budget and one stop
(W34, W35). A client over a bare `Session` keeps them in memory, as before. A ledger that cannot be
read refuses every write and is left as it was. `dumpstagram.session.clear_write_stop(path) ->
bool` and `dumpsta session --clear-write-stop` lift a stop and keep the hour's departures (W36).

### The rotation canary

`dumpsta doctor` compares each stored `doc_id` with the one the website's current bundles compile,
and with `--live` replays the ten capability reads once. It is a dry run without `--live`, exits
12 on drift and 13 on a failed replay, and never sends a write. It is private to the command, so
it adds nothing to the public surface (W31 to W33).

### Behaviour changes under the same surface

- The event listener's poller reads a known thread back with its last known message as
  `newer_than_message_id` on every page, keeping the three page bound and the gap marker (W10).
- The feed and profile posts queries moved to the ids the website compiled on 2026-09-24 after
  both old ids were seen still answering. This is an upstream repair, `_private` only.

## Rulings that shape the API

W1 and W19 to W21 fix the namespaces and their names, W23 to W25 the iterators, W26 to W29 the
media model and downloads, W31 to W33 the canary, W34 to W36 the ledger, and W37 to W40 posting.
W10 fixes the poller's read back. The other rulings of W1 to W44 govern layout, gates, discovery
and later phases, and change nothing a caller calls. All are in
[../web-parity-plan.md](../web-parity-plan.md).

## Known limitations and risks

- Every upload is a write (W38). It is sent once, spaced by the write spacing, counted against
  the write budget and stopped by the write stop, so a photo costs two writes and a carousel of n
  images costs n + 1. A publish that fails after an upload applied raises the failing write's own
  error with a note beginning `posting:` naming the orphaned upload ids. What an orphaned upload
  costs is unresolved.
- `dumpsta delete-post` reports a post `gone` only when the read after a delete that answered
  `did_delete` true is refused with error code `1675030`, the code all five deleted posts the
  engine read back answered with (W39). A read refused any other way is reported unknown. That
  literal sits in `_cli/commands/posting.py`, outside the provenance gate's failure code scope
  of `_private/web`, so the provenance gate does not check it.
- Only JPEG uploads were observed, so only JPEG is accepted. Video, reels, stories, caption
  edits, location, tags and collaborators are not posted. The carousel's upper limit is left to
  the upstream, unobserved.
- Downloads take no pacer slot and run up to four at once per client. Whether a burst of CDN
  fetches far beyond a browser's is scored against the account is unmeasured, and five fetches in
  one evening say nothing about it (W26).
- Only the write budget and the write stop are shared across processes. Write spacing, read
  spacing and throttle holds stay per process, so two processes can place writes closer together
  than the write floor, and the budget still bounds them (W34). No gate runs the `dumpsta` write
  commands themselves in two processes. The cross-process gates run the engine's own write path
  in two interpreters. The ledger uses `fcntl`, so it is POSIX only.
- `dumpsta doctor`'s last live run, at `--bundle-limit 150`, read 14 of its 30 operations
  `missing`: no scanned bundle compiled them. Missing is not drift (W31). Five engine operations
  are known to live only in lazy chunks no document names, so they read missing on every run,
  and which of the rest the default cap of 1000 finds is unknown. The canary checks the ten
  GraphQL writes by artifact only and does not check the posting routes, which are REST and not
  in the query registry. That zero drift run used the existing session file, not a freshly
  adopted one.
- The operation census that measures coverage, 265 operations of which 20 back a capability, is
  a lower bound. Lazy chunks load only when a control is used, and the explore grid, the
  notifications list and the audio page load their content over REST routes that the census does
  not record (INFERENCE).
- The engine adopts an existing browser session and cannot log in.
- The listener polls the inbox every 60 s by default and marks nothing seen.
- Human timing rests on one measured sample, taken on one day.
- Token lifetime has a lower bound and no upper bound. The engine re-reads its tokens when the
  upstream rejects them.
- Everything was measured on one account, from one residential IP, against the web surface.
  Group threads, the mobile API and any non-residential network are unmeasured.
- aarch64 macOS on CPython 3.12 is the only verified platform. Intel is unverified.
- The source distribution ships the gates and the scripts they load. The gates that read git
  fail outside a git checkout, and the recorded oracle's fixtures stay local, so its gates skip
  outside the author's checkout.

## Departures from browser parity

Added in this release, each recorded in `docs/web-request-contract.md`:

- `x-web-session-id` is not sent on the upload or the publish, where the browser sent a three
  part id its page generates, and `x-ig-max-touch-points: 0` is not sent on any of the four
  posting requests.
- The post delete leaves out `__s`, `__dyn`, `__csr`, `__hsdp`, `__hblp` and `__sjsp`, the page
  fields every GraphQL request here leaves out.
- The browser sent a carousel's uploads at once and the publish 3.4 s later. The engine sends
  each as its own write, spaced by the write spacing, so under `PARITY` a carousel of two takes
  over a minute (W38). `FAST` removes the spacing.
- The browser's Share also sent `usePolarisCoppaEnforcementStatusViewerQuery` and the page's own
  logging, and its delete was followed by the profile page's reload. None of it is sent, and the
  engine never opens the composer, so the upload's `referer` is the home page.
- A download is a CDN fetch outside any page, with no cookie, up to four at once.
- `dumpsta doctor` is not browser traffic at all. It loads two documents, fetches bundles without
  a cookie, and sends each read alone. It runs only when a person asks for it.

Carried over from `1.0.0`:

- The notes tray read is sent alone. A browser sends it as one of ten queries in an inbox load,
  which is not modelled.
- A post read, a like and an unlike are each sent alone, without the post page's document and
  companions, and without the Relay layer's `actor_id` and the feed item's
  `organic_tracking_token`.
- A comment page read, a comment and a comment delete are each sent alone. The first comment page
  uses the pagination query rather than the page's own container query, and the page size of 10
  is an assumption.
- A follow and an unfollow are each sent alone, without the page the follow is made from.
- A direct text send and an unsend are each sent alone, with the thread page as the referer, and
  without the browser's performance logging fields.
- A note set and a note delete are each sent alone, without the inbox load and the composer's
  bootloader requests around them.
- The listener's polling is itself a departure, whatever the preset, because no browser was seen
  re-reading the inbox listing on a timer, and it leaves out the thread open and the mark-read
  mutation a browser sends around a thread it reads.

## Upstream repairs

- `PolarisFeedRootPaginationCachedQuery_subscribe` and `PolarisProfilePostsQuery` moved to the
  `doc_id`s the website compiled on 2026-09-24 (`f6ae9c5`). The first live `dumpsta doctor` run
  reported both drifted while the old ids still answered, each new id was replayed twice through
  its own builder and mapper, and a second run reported zero drift.
